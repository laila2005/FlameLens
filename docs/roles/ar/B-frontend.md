# الدور B: قائد الواجهة (Frontend)

[English version](../B-frontend.md) · [اختر دورك](../00-choose-your-role.md)

**الاسم:** Yousseif  **البديل:** ______  **يعمل مع:** C

## مهمتك في جملة واحدة

حوّل النموذج التجريبي للوحة (mockup) إلى التطبيق الحقيقي: واضح وسريع ومقروء على شاشة الهاتف، وصريح دائمًا بشأن البيانات التجريبية وعدم اليقين.

## الخبرة المطلوبة

| | |
|---|---|
| **مطلوب** | أساسيات React وTypeScript، HTML وCSS، استدعاء API بـ `fetch` |
| **ميزة إضافية** | Tailwind، Vite، تصميم متجاوب، Figma، إمكانية الوصول (accessibility) |
| **تتعلمه خلال يومين** | Tailwind، Plotly داخل React |
| **صفات شخصية** | ذوق بصري، اهتمام بالتفاصيل الصغيرة |

## ما تملكه

هيكل التطبيق، اختيار الـ habitat، بطاقات الترتيب، تخطيط Evidence case وRun this next وSafer options، عرض المقارنة (diff)، عرض الرحلة (journey)، الثيم، والشكل النهائي للعرض.

## قبل الهاكاثون

### B1. افهم النموذج التجريبي (الإثنين 9 نوفمبر، 45 دقيقة)
افتح [النموذج التجريبي للوحة](../../links.md) وجرّب كل شيء. في `docs/design/ui-inventory.md` اكتب كل عنصر وما يفعله: المنزلقات والإعدادات الجاهزة والبطاقات والتبويبات ولوحة الأدلة واللافتة.
يُعتبر منجزًا عندما: تحتوي القائمة على 25 عنصرًا على الأقل ويوافق زميل أنها كاملة.

### B2. تجهيز البيئة (الإثنين 9 نوفمبر، 20 دقيقة)
شغّل `python scripts/check_env.py`. تأكد من عمل Node 20 أو أحدث وnpm. اقرأ صفحتي البدء السريع لـ Vite وTailwind.
يُعتبر منجزًا عندما: يُظهر check_env أن Node بحالة OK.

### B3. تصميم الشاشات (الثلاثاء 10 نوفمبر، ساعتان)
ارسم على الورق أو Figma هذه الشاشات واحفظ الصور أو رابط Figma في `docs/design/screens/`:
1. اختيار الـ habitat مع قائمة الترتيب
2. لوحة Evidence case
3. لوحة Run this next
4. لوحة Safer options
5. صفحة lens
6. عرض المقارنة
7. رحلة الأجواء (المراحل في صف واحد)

كل شاشة تحتاج أربع حالات: **عادية، تحميل، فارغة أو بلا دليل، خطأ**.
يُعتبر منجزًا عندما: توجد الشاشات السبع بحالاتها الأربع وقد رآها C.

### B4. عناصر التصميم (Tokens) (الثلاثاء 10 نوفمبر، 45 دقيقة)
في `docs/design/tokens.md` اكتب الألوان والخطوط والمسافات المأخوذة من النموذج: خلفية كحلية داكنة، برتقالي اللهب، سماوي بارد، خط Sora للعناوين وIBM Plex Sans للنص وIBM Plex Mono للأرقام. أضف قيم الثيم الفاتح.
يُعتبر منجزًا عندما: يستطيع زميل تنسيق زر من الملف وحده.

### B5. قائمة المكونات (الأربعاء 11 نوفمبر، 90 دقيقة)
في `docs/design/components.md` اكتب كل مكوّن React مع الـ props والحالات: `HabitatPanel` و`InvestigationCard` و`ScoreBars` و`EvidenceCase` و`StrengthGauge` و`NextExperiment` و`SaferOptions` و`LensTabs` و`EvidencePanel` و`SampleBanner` و`JourneyRow`.
يُعتبر منجزًا عندما: يذكر كل مكوّن البيانات التي يحتاجها (تطابق [API contract](../../05-architecture-and-api.md)).

### B6. قرارات المكتبات (الأربعاء 11 نوفمبر، 45 دقيقة)
قرر: التوجيه (على الأرجح بدون)، إدارة الحالة (React state يكفي)، غلاف Plotly (`react-plotly.js` أو Plotly مباشرة). اكتب أوامر التثبيت التي ستشغلها عند الانطلاق في `docs/design/setup-commands.md`.
يُعتبر منجزًا عندما: تستطيع إعداد المشروع في 10 دقائق من الملف.

### B7. قائمة إمكانية الوصول والهاتف (الأربعاء 11 نوفمبر، 30 دقيقة)
اكتب 10 فحوصات في `docs/design/ui-checks.md`: الوصول بلوحة المفاتيح، التباين، عدم وجود تمرير أفقي عند عرض 400px، تسمية المنزلقات، ظهور لافتة العينة دائمًا، وغيرها.
يُعتبر منجزًا عندما: تستطيع F استخدامها ضمن خطة الاختبار.

### B8. الاتفاق على الواجهات مع C (الخميس 12 نوفمبر، 45 دقيقة)
مع C اتفقا على الـ props بين اللوحات والرسوم وعلى بيانات JSON الوهمية لـ `/case` و`/next` و`/alternatives` و`/strength`. احفظها في `docs/design/mock-json.md`.
يُعتبر منجزًا عندما: توافقان معًا في الدردشة.
